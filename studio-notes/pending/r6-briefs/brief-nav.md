## Build (one small shared mechanism, not per-page hacks)
1. **Hub state memory:** the hub records where you are — view, Templates collection/category, Saved collection/chip/sort, Plan tab, and scroll position (window + any horizontal scroller that matters) — in `history.state` (`replaceState`, throttled) and `sessionStorage` (per hash). When the hub page is shown again (back/forward navigation, bfcache `pageshow`, or a fresh load reached by Back), it restores all of that, scroll included, after the async content has rendered (wait for the grid; retry briefly, cap ~1.5 s; `history.scrollRestoration='manual'` on the hub).
2. **Drill-ins inside the hub get their own Back step:** opening a collection in Templates or in Saved pushes a history entry (through `Studio.nav` or the view mechanism — never a second ad-hoc pushState system; follow the existing patterns), so the phone's Back from a collection returns to the full list at the same scroll, and Back from the list returns Home.
3. **Top-left Back on every other page** (tool pages, Create, Video, Board/lab, What's New, Brand kit, any page with a back link): one shared helper (e.g. `Studio.goBack(fallbackHref)` in studio.js; pages that don't load studio.js get a tiny inline equivalent) — when the previous history entry is a Studio page of the same origin (`document.referrer` same origin + `history.length>1`; also mark in-app links with a sessionStorage breadcrumb so it works even when referrer is stripped), do `history.back()`; otherwise go to the fallback (the hub, at the right view: e.g. Templates for a design opened from Templates if known). It must go through the leave prompts (`needAsk()` → `leavePrompt(...)`) exactly as today: when the person chooses Leave / keep draft, the prompt's navigation uses the same back logic instead of `location.href=href`. Label: "Back" (not "All tools") wherever it no longer always goes to All tools; keep `aria-label` accurate.
4. **Phone back gesture** on tool/Create pages already goes to the previous page (browser); make sure the hub then restores (item 1). Check bfcache isn't blocked needlessly (an `unload` listener blocks it — grep; `pagehide` is fine).
5. Walk these journeys and make each return exactly: Templates → collection → open template → Back (button AND history back) → same collection + scroll; Saved → collection → open design → Back; Saved scrolled far down → open → Back → same scroll; Home → Continue editing → Back; Search → open a result → Back (search state may reset, but view + scroll should be right); Plan → Ideas tab → Back from a page opened there; What's New opened from Settings → Back; Home → tool → Back → Home (top). Deep link opened fresh (no history) → Back button → the hub (fallback), never a blank/closed tab.
6. Don't break: `nav` suite rules (never step back while leaving; `?render=1` frames do nothing), the Plan shell's own Back, select mode Back, search overlay Back.
