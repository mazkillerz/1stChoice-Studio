## What changed
- **Backgrounds (#39)** in Cinematic (all 3 styles), New place (all 4), Offer (White, Cream, Black; not Full photo) and Collage (the gaps and margins, all 3 looks): `Studio.groundField(...)` right under the background colour in the Style sheet, and `h.ground(colour, o.value('gfx'))` instead of `fillRect`.
  - New place: the ground has a see-through window. With a finish the tool clips to "everything but the window" and calls `h.ground` inside it; with Plain / no value it runs the old `fill('evenodd')` line untouched. The Cream look's warm ring around the window is drawn after the finish, as before.
  - Plain / no value is pixel-identical: proven in `tests/backgrounds.mjs` (no value = Plain in every style of the four tools) and once more by hand against the base commit (old worktree on :8091 vs branch on :8081, every style of the four tools: same hashes).
- **Finish row only where it shows (UX):** I measured each style of Restock, Photo story, Cinematic, New place, Offer, Collage with Dots, Glow and Fade (share of pixels that change). 0% on Restock Full photo, Photo story Full / White frame / Whole and Offer Full photo; 1–68% everywhere else. Restock and Photo story's `when` lists already hide the row on exactly those styles, so they needed no change (and stay outside my scope). Offer now hides it on Full photo. Cinematic, New place and Collage show it on every style (Collage: it shows in the gaps and outer margin; with no margin and gap 0 nothing shows, but `when` can't express that and it's a rare setting).
- **Templates with a finish (#40):** two presets in `brands/1stchoice/brand.js`, both badge New, words only from approved phrases:

## Notes
- **Backlog:** #39 done for Cinematic, New place, Offer, Collage (Highlight covers still left out on purpose). #40 done (two presets). New finding for the backlog, outside my scope: **New place "Save the frame only (see-through PNG)" is not see-through when a photo is in**: `renderPage(pg,K,withPhotos)` always calls `draw()`, which draws the photo; `withPhotos=false` only skips the black backing. So the "frame" PNG has the photo in its window (checked on the base commit with Plain: window alpha 255). Either skip `h.photo` when saving the frame, or rename the button. Engine (`studio.js` save engine), so for the lead / 1.30 Simplify.
- **Lessons:** Offer (and every tool with a photo) refuses to save with only the example photo ("Add your photo first"); a save test must `setInputFiles('#pick', …)` first. The first page load in a fresh browser can hash differently from the next (fonts / photo decode); in old-vs-new pixel checks, warm up once or compare the second load.
- **Flaky check seen once:** "Grain draws the same pixels after reloading the page" (section 3 of backgrounds.mjs) failed in my first run and passed in the next three, with no change to Grain or Restock. Probably the reload's `settle()` catching a frame before the can pictures finish; worth a longer settle if it shows again.
- **Taste:** answers the open question "Which other tools want backgrounds (Cinematic, New place, Offer, Collage gaps)?": all four now have them, Plain by default. Still ask the owner whether finishes are strong enough on white on a real phone.
