## 1. What changed

### 1.1 Swipe across saved designs to tick several (like Photos)
- **Select mode, phone:** a finger that starts **sideways** on a design starts a swipe; every design between the first one and the one under the finger is ticked (grid order, so going down a row ticks the whole run, like Photos). Going back inside the same swipe unticks what it left (back to how it was before the swipe). Starting on a ticked design **unticks** the run.
- A finger that starts **up or down** still scrolls the page, and ticks nothing. While a swipe runs the page never scrolls by accident: `touch-action: pan-y` on the cards in select mode + a non-passive `touchmove` that cancels only while a swipe is running (or a held design is about to become one).
- **Edge scroll:** holding near the top (64px) or just above the action bar scrolls slowly (≤16px a frame) so a long run can go on; it stops when the finger moves away.
- **Outside select mode, phone:** press and hold a design (the menu opens as before), then drag: the menu closes, selecting starts with that design, and the run is ticked. Hold without moving = the menu, unchanged. A quick sideways swipe outside select mode does nothing.
- **Computer:** in select mode a mouse drag (6px+) ticks the run the same way; no text gets selected (`body.swiping` turns off user-select). Outside select mode a drag does nothing (unchanged).
- A swipe never opens a design (the click that ends it is swallowed only inside the grid, and only for 400ms); a plain tap/click afterwards ticks one as before.
- A finger or mouse in the gap between designs counts as the nearest design (≤24px), so a run does not stall between columns.
- Light haptic tick per change, the title counts as before ("5 selected").
- `startSelect(id,keep)`: `keep` repaints only the select state (not the grid), because the finger is still on one of the grid's cards (re-rendering it would lose the finger's events). Every existing call is unchanged.
- **Taps:** tick a row of 3 designs: Select + 3 taps = **4 → 2** (Select + one swipe). Tick 7: 8 → 2. From the grid without Select: press and hold + drag = **1 gesture**.

### 1.2 The "/" key in the Studio search (backlog #45)
- On a computer (`hover:hover` and `pointer:fine`) the empty search field shows a quiet key cap **/** at its end (muted text, 1px line border, 22px, 12px weight 500). It hides while the field is focused or has text, and never shows on touch. Added by `search.js` (`kbd.us-kbd`, `aria-hidden`), and the field gets `aria-keyshortcuts="/"`. The "/" shortcut itself already existed (1.30.0).
- Contrast: 6.7:1 light, 8.7:1 dark.
