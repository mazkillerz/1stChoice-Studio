## 1. What changed

### 1.1 Flip for the tool's own photos (backlog #32)
- Photo sheet: a **Flip** button (quiet `.mini`, icon + word, 48px, pressed = accent ring like the layer Flip) under Zoom / Reset photo, above Photo look. Shown only for a real photo in a box that is used (same rule as the look row; also for "whole photo" boxes where Zoom hides).
- `h.photo()`: when `p.flip`, the photo is mirrored around **its own centre** (not the box's), so dragging still moves it the same way and its position is kept; the photo look (`photoFx`) covers the same rectangle, so looks work unchanged. `h.backdrop()` (the blurred copy behind a whole photo) mirrors too.
- Recipe: `photos[i].flip:true` only while on; no key otherwise. `applyRecipe` sets or deletes it, so Undo/Redo, drafts, saved designs, `?render=1` frames and Save pictures all follow. **Old designs pixel-identical**: no key = `undefined` = `false` = the same drawing path as before (the new code is inside `if(p.flip)`); proved in `flip.mjs` by hash.
- It belongs to the photo: Swap two, hold-and-drag and Shuffle move it with the photo; a new photo in that box starts unflipped (a look carries over, a flip does not: a flip is about that picture). "Put everything back where it started" (Layers) clears it with zoom/position; "Reset photo" leaves it.
- The slot thumbnail and the Photo look previews mirror with it (CSS `scaleX(-1)`).
- Tap count: flip a photo = Photo tab, Flip = 2 taps (phone, the sheet is often open already after adding a photo: 1).

### 1.2 `tools/highlight-emoji.js` loads only when needed (1.28.0 audit)
- `tool()` no longer loads it on every tool page; it loads `assets/stickers.js` only. New `emojiStickers()` in studio.js loads the file once and calls `window.addEmojiStickers()` (new in stickers.js; it also runs at load, so a page that already has `HL_EMOJI`, i.e. Highlight covers with their script tag, gets the emoji stickers straight away).
- When: the **Layers** sheet opens on a phone (prefetch, so it is there by the Sticker tap), a press on **Sticker** (computer), or a design/draft/undo step/preset that has a `sticker:emoji-*` layer (`applyRecipe`), which draws again when it arrives.
- No missing emoji in pictures: `assetsHD()` (awaited by Save and by `Studio.renderer.page()` in `?render=1` frames) now also waits for the file while it loads. Tested with the file delayed 2.5 s: the render-frame picture still has the heart.
- Sticker sheet: opens with the emoji (waits for them up to 1.5 s if not loaded yet, then opens anyway and adds them when they arrive). Found by `stickers.mjs` on desktop: opening first and adding the emoji later grew the card past the screen after it scrolled into view.
- `paintStickers()` repaints when the sticker count changes (key = text colour + count).
- **For 1.31.0 (Create stickers):** Create's own page must load `tools/highlight-emoji.js` before `assets/stickers.js` (script tag), or load it later and call `window.addEmojiStickers()`. If Create calls studio.js `tool()` it gets `emojiStickers()` for free; it does not (own editor), so a script tag is simplest.
