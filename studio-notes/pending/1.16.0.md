## README lines

Under Templates:
- **Favourites**: tap the star next to a template's name; it shows in a Favourites section at the top of Templates (All) and first in its category. Tap again to take it out.
- **Recently used**: the last templates you opened, in one row under Favourites (4 on a phone, more on a computer). Both lists are kept on this device, per brand.
- Create's template picker has the same stars and a Recently used row (up to 3), shared with the Templates page.

## How it is built (for lessons / skill Repo notes)

- Storage: `studio:tplFav:<brand>` and `studio:tplRecent:<brand>` (localStorage via `store()`, arrays of entry ids, newest first, recent capped at 8). Entry ids are the Templates ones: `p:<preset>`, `t:<create template>`, `team:<design id>`. Create's picker reads/writes the same keys with `t:` ids, so a star in either place shows in both. Bad values (not an array, non-strings) are ignored, never thrown.
- `assets/templates.js` is still brand-agnostic: stars only appear when the page passes `favKey`/`recentKey` to `StudioTemplates.init` (the hub does in `showTemplates()`); `StudioTemplates.mark(store,key,id,max,on)` is the shared "put this id first" helper. A card is recorded as recently used on tap, before navigating (also for open-in-new-tab). On a back-navigation from the browser cache (`pageshow` persisted) the body is redrawn so the new Recently used row shows.
- Star placement: a sibling of the card link (no button inside `<a>`), at the end of the title line; vertical position uses container units (`100cqw * --ar`, the preview's shape ratio) with a bottom-aligned fallback. In All, starring redraws and scrolls by the shift so the tapped card stays put; in a category, and in Create, only the star flips (nothing jumps under the finger) and favourites go first the next time the list is drawn.
- Create picker cards are now wrapped in `.cr-tw` (the search hides the wrapper); Recently used cards are `.cr-rec[data-rtpl]` (a different attribute, so `[data-tpl=…]` selectors and the search counts in older suites are unchanged); the Recently used block hides while searching.
- The New badge moved from the preview corner into the sub line (`.tp-s`); `tests/templates.mjs` badge checks updated to match.
- New brand-kit field: `create.templates[].sub` (English) → the line under the title in Templates; without it the old "Story · Create" stays.
- Files touched outside the listed scope: none. In `home()` the change is `tplEntries()` (sub) plus the `favKey`/`recentKey` options on the `StudioTemplates.init` call right below it in `showTemplates()`.

## Lessons note

- A function declaration inside a closure hoists and silently shadows a module-level one with the same name (`mark()` for chips vs the new `mark(store,…)` helper): the page looked right (redraw + "Added to favourites") but nothing was saved. The new suite's storage checks caught it. Give module-level helpers distinct names, and always assert what was written to storage, not only what the UI shows.
