## README lines

Under the tool page's Layers section:
- **Sticker**: a sheet of 14 drawn stickers (arrows, sparkles, starburst, star, heart, seal, scribble circle and underline, wavy line, speech bubble, shine lines, tick). Each is a normal layer: move, size, turn, recolour (brand colours or custom), opacity, duplicate. Drawn as vectors, so they are sharp in the 2160×3840 save. No words inside, so any brand can use them.

## How it is built (for lessons / skill Repo notes)

- `assets/stickers.js` defines `window.STUDIO_STICKERS` (id `sticker:<name>`, label, native `w`/`h`, start width `w0`, `draw(c,color)`) and `window.paintStickers(el)` (the picker tiles, drawn in the text colour, repainted when the theme changes). Each sticker is one fill or one stroke so opacity has no darker overlaps. **Never rename a sticker id: saved designs point to it.**
- In the engine a sticker is an ordinary added asset layer `{type:'asset', ref:'sticker:<id>', w, x, y, color}`; `assetDef()` resolves `sticker:` refs from the list, `drawShape()` calls `a.draw` (scaled), the layer kind is `'sticker'` (Layers list says "Sticker"). So move, size, turn, colour, opacity, duplicate, delete, order, copy/paste style, undo and the recipe all come free. The inspector shows Colour only (no None / outline / corners) for stickers.
- `tool()` starts loading `assets/stickers.js` alongside `useBrand()` and waits for it before building the page, so a saved design with stickers draws them on open and on save. If the file can't load (offline before the shell has it), there is no Sticker button and designs that have stickers keep them in their recipe (drawn empty, never lost).
- Old designs: no recipe change; the suite checks a 1.7.0-style design draws pixel for pixel the same with and without stickers.js.
- Older Studio versions opening a design with a sticker: `assetDef` returns null → an empty layer, no crash, the sticker stays in the recipe.
